真正持久的竞争力，是方法论。

工具是放大器，方法才是根基。具体来说：

- 你需要理解大模型的能力边界——它擅长什么、不擅长什么、什么时候该信任它、什么时候该介入；
- 你需要掌握与 AI 协作的方法论——怎么把需求变成 AI 能精准执行的规范，怎么在关键决策点保持人的判断力；
- 你需要有架构能力和领域知识——AI 能帮你写代码，但它不能替你做架构决策，不能替你判断技术选型的长期影响。

这些东西不会因为某个工具的源码泄漏了就贬值，也不会因为某个工具出了新版本就过时。恰恰相反，工具迭代得越快，方法论的价值就越高——因为只有掌握了底层方法的人，才能在工具更替中始终保持生产力。

AI 的输入质量和输出质量呈现阶梯式关系。也就是：人想的越清楚，AI做的越准确。瓶颈不在AI的能力上，而在人的思考质量上。

必须要有足够的技术判断力来验证他的输出，需要判断写的代码对不对？

AI提效不是速度变化，而是精力分配的变化。之前我们的时间在“修bug、review代码、写测试、写文档”等这些又多又碎的事情上，可以让AI把这些接过去，我们就可以把大部分精力集中在“架构设计和核心决策”上。这个改变是复利的。

因此 人是架构师，ClaudeCode/Agent是工程团队。具体的分工：

- 第一层，必须人做的。产品边界、架构决策、技术取舍、跨模块一致性。
- 第二层，AI做人验收的。业务代码、接口开发、前端页面、测试用例、文档。这是工作量的大头。有一个硬标准：任何一行代码你都要能说清楚它在干什么。说不清楚，就不能用。
- 第三层，AI全权处理的。格式化、样板代码、简单重构、启动脚本、Makefile。扫一眼没问题就行。

当然这三层不是固定的，比如做应用层项目，第二层比例大，AI可以写更多代码。做基础设施层项目（分布式系统、存储引擎），第一层比例大，核心代码最好自己写。重点是我们始终需要清楚哪些东西不能放手。

还有一点，有时候我们没有完全想清楚项目要怎么做？可以让 Agent 帮我们梳理思路，我们来判断取舍。这种就是协作模式。

如何检查/验收 Agent 给人的东西？

- 查看意图，AI 做的是不是我们让他做的？比如我们让AI实现一个删除接口，但他额外加了一个软删除机制（不是真删，标记deleted=true）。软删除也许合理，但问题是我们没有要求，AI 自作主张扩大了范围。这次看着还行，下次可能就顺手加了不合适的东西了。
- 查看质量，风格、规范、一致性。一个项目中，功能也许没有问题，但风格如果不统一，时间长了维护起来很痛苦。
- 查看边界，错误处理、异常、潜在风险。比如接口的并发性？

### 规范驱动开发

Specification Driven Development，SSD。先定规范，再让AI按规范执行，而不是直接让他写代码。

- 规范不是一次性的指令，是一套体系。ClaudeCode没有长期记忆，每次新对话，对他来说都是从零开始。
- 写好 prompt 是一次性技巧，SSD是贯穿整个项目生命周期的方法论。

SSD的完整工作流：

- 第一步，定规范。
  - 最容易跑偏的地方有：代码命名风格、返回格式、错误码体系、设计原则（过度的设计模式是负担而不是资产）。
  - 规范一般是经验，也可以让 ClaudeCode 帮我们梳理“项目要定哪些规范”。
  - 规范放在项目根目录的 CLAUDE.md 的文件里。ClaudeCode每次启动新对话时会自动读取这个文件。
- 第二步，下达任务时，明确引用规范。
  - 不是“帮我做个Agent CRUD”，而是“按照 CLAUDE.md中的规范，实现Agent的CRUD接口”。
- 第三步，人验证输出
- 第四步，迭代规范。每次AI跑偏，查看规范是否没有覆盖？并且补上那条规范。

有用的规范：

- 具体，不模糊。
  - 没用的规范，“代码要简洁”，ClaudeCode对简洁的理解不一定和我们一样。
  - 有用的规范，“不引入不必要的设计模式（工厂、策略、观察者等），除非明确要求。每个功能用最简单直接的方式实现”。
  - 判断标准，ClaudeCode看到这条规范后，不应该猜我们的意思？如果需要猜，那就不够具体。
- 有优先级，不贪多。
  - ClaudeCode的上下文窗口是有限的，太多的规范反而会稀释重要的那几条。
  - 原则：AI反复跑偏的地方写细，不跑偏的地方不写
- 带上原因，不只是规则。
  - 对于涉及工程权衡的规范，不能只告诉ClaudeCode不要这样做，还要告诉他为什么。他需要理解约束的原因，才能在类似场景中举一反三。
- 规范需要分层，随着项目推进，规范会越来越多，需要分层管理
  - 全局规范。写在 CLAUDE.md 里，整个项目通用。命名规则、接口格式、错误码体系、设计原则、行为约束。项目初期定好，后面很少改动。这是地基。
  - 模块规范。某个模块开发前单独定义。写在模块目录下或者开发前的指令里。
  - 任务规范。每次给 Claude Code 下达具体任务时的补充说明。临时性的，不落成文档

### 顶层设计

CLAUDE.md 是我们和 AI 的合作协议。五层结构从宏观到微观，项目上下文→架构→代码组织→数据库→接口 + 行为指令。根目录放全局规范，子目录放模块规范，两者叠加生效。

Skills 是可复用的规范片段。发现指令在重复，就该创建 Skill。

### 协作模式

- 执行模式。人很清楚，给 cc 指令，cc 去做，人来验收。这种场景任务很清楚
- 咨询模式。人知道大方向但不确定细节。先问 cc，cc帮人梳理，人判断取舍，人再给指令执行。适合不确定性高的场景。

概念说明

- plugin 就是 一套好用的 commands+hooks+skills 的组合。价值在于：可复用、可版本化、可分发
