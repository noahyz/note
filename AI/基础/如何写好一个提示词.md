prompt（提示词）是人机交互的桥梁，可以准确指明任务的方向和输出期望。

### 一、日常的prompt架构

常见的Prompt架构主要分为两类：一类是三段式（RTF）架构，另一类是新加坡科技局举办的提示词工程大赛冠军CO-STAR架构；这两种架构都是现在常见的Prompt架构，可以满足日常生活的使用。

### 二、结构化prompt

最常使用的就是 markdown 标题法。

结构化的提示词通过分层和模块化的方式，能够更清晰地组织任务信息，尤其在复杂任务中表现出显著的优势。通过分隔符进行层级结构区分实现权重分配，**模型注意力更集中**；构成要素的不同，可以将整个Prompt的内容边界区分清晰，**防止模型出现大量的幻觉**；通过结构化与构成要素的结合，在实际应用中，可以更方便的去进行单独模块的内容调增，**易于修改**。

- 标题，构建文章骨架
- 无序列表，罗列平级观点
- 有序列表，展示步骤或排名
- 任务列表，代办事项或检查清单
- 引用块，引用文本或强调说明
- 行内代码，强调关键词或术语
- 分割线，视觉分隔

### 三、核心要素

如下是“企业级结构化架构”的核心要素。使用这个思路效果会更好。

##### 1. Role（角色）

 定义模型的身份和职责，让模型明确其定位，调用该角色领域下的知识，激活模型专业能力，产生符合角色习惯的回答。比如：
```
# Role  
你是一位能够帮助我正确选取物品的专家。
```

##### 2. Background（背景）

提供任务的背景信息，帮助模型理解上下文信息。例如：
```
## Background  
我需要你，根据我给出的图片，去帮我判断选取的物品是否正确。
```

##### 3. Goals（目标）

明确任务的预期结果，设定具体目标，将模型当作你的实习生。例如：
```
# Goals  
根据给出的图片，以及我的标签定义严格执行"""workflow"""中的流程，判断我选取的物品是否正确并最终输出结果。 
```

##### 4. Constraints（限制）

设定任务的约束条件，避免偏离主题，胡思乱想。例如：

```
# Constraints  
- 不得选取图片中不存在的东西，若选取不存在的物品即是错误。
- 严格完成我给你制定的目标，按照"""Workflow"""中的流程一步步执行，最后严格按照"""Format Information"""的格式进行输出
- 严格按照"""Format Information"""中给定的输出内容和输出格式输出
```

##### 5. Information Definition（信息定义）

 统一上下文中的名词术语，以及初始输入内容，规范表达、明确任务中涉及的名称代表的是什么内容，可以让人和模型都清晰理解。例如：

```
# Information Definition  
选取的物品图片：{{选取的物品图片url链接}}  
```

##### 6. Workflow（工作流程）

 指导模型完成任务的步骤，让模型像机器一样一步一步执行动作；注意一定要确保模型存在容错兜底结果。例如：

```
# Workflow  
1. 理解"""Information Definition"""中的所有变量名称对应的内容，完成后执行步骤2；
2. 查看"""Label Definition"""中关于标签名称、标签定义、驳回规则、通过规则的描述，结合步骤1中的内容，判断是否符合驳回规则或通过规则，并执行步骤3。
3. 当选取的物品符合通过规则时，根据"""Format Information"""要求的格式输出，并立刻停止判断，否则执行步骤4；
4. 当选取的物品符合驳回规则时，根据"""Format Information"""要求的格式输出，并立刻停止判断，否则执行步骤5；
5. 当无法判断符合驳回或通过时，根据"""Format Information"""要求的格式输出内容为“无法确定”，并立刻停止判断。
```

##### 7. Label Definition（标签定义）

 定义标签的名称、含义及规则；为确保模型理解具体，输出符合预期，此处的规则需要进行举例和详细解释说明。例如：

```
## Label Definition  
- 标签名称：判断选取物品是否为纸巾
- 标签定义：需要根据选取的物品图片，判断选取物品是否为纸巾  
- 驳回规则：当选取的物品不为纸巾时，选取的物品错误。例如：选取的是水杯，不是纸巾，选取的物品错误。  
- 通过规则：当选取的物品是纸巾时，选取的物品正确。  
```

##### 8. Format Information（输出信息）

只要Prompt没有结束，模型就可以在输出的末尾持续延伸，修改甚至否定之前的结果和定义，因此需要明确定义输出内容和结构。
定义输出格式和结构，通常非枚举使用JSON格式输出内容，枚举使用“是/否”，“驳回/通过”等。例如：

```
# Format Information  
严格按照如下的JSON格式输出：
{
  "选取的物品是否正确": "正确/错误",
  "选取的物品是什么":"水杯"
}
```



### 三、经验总结

一定不能做的是：

- 禁止情绪化表达。 禁止在书写提示词的过程中，使用多个标点符号，需要做的是清晰化表达，而不是通过情绪传达来让模型理解正确
- 输出格式无限制。 输出格式必须限制，否则输出结果五花八门，下游数据不能使用；常使用JSON/穷举输出
- 定制解决问题。直接告诉模型答案
- 全文都是重点。不要把全文中的所有内容都标记为重点
- 多个输出要求。 多个输出要求导致模型前后混乱，无法正确输出想要的格式
